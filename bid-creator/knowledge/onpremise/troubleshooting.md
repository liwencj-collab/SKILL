# 私有化部署故障处理手册

## 故障排查流程

### 1. 排查步骤

```
┌─────────────┐
│  1. 收集   │  →  现象/时间/操作
└──────┬──────┘
         ↓
┌──────▼──────┐
│  2. 定位   │  →  日志/监控/排查
└──────┬──────┘
         ↓
┌──────▼──────┐
│  3. 制定   │  →  方案/验证
└──────┬──────┘
         ↓
┌──────▼──────┐
│  4. 解决   │  →  执行/验证
└──────┬──────┘
         ↓
┌──────▼──────┐
│  5. 复盘   │  →  总结/预防
└─────────────┘
```

### 2. 常用排查命令

```bash
# 系统资源
top -H                    # CPU/内存
df -h                     # 磁盘
free -m                   # 内存
iostat -x 1              # IO

# 网络
netstat -tunlp             # 端口
ss -s                     # 连接数
tcpdump -i eth0            # 抓包

# 进程
ps -ef | grep java        # Java 进程
jstack <pid>             # 线程堆栈
jmap -heap <pid>         # 内存

# 日志
tail -f app.log          # 实时日志
grep "ERROR" app.log      # 错误日志
```

## 常见故障及处理

### 1. 服务无法启动

**现象**：启动失败，端口被占用

**排查**：
```bash
lsof -i:8080          # 查找占用端口的进程
ps -ef | grep java     # 检查进程
cat startup.log        # 查看启动日志
```

**解决方案**：
- 端口占用：kill 进程或更换端口
- 配置错误：检查配置文件
- 权限问题：chmod/chown

### 2. 内存溢出 (OOM)

**现象**：服务崩溃，OOM 错误

**排查**：
```bash
dmesg | grep -i oom     # 系统 OOM
jmap -heap <pid>        # JVM 堆内存
jmap -histo:live <pid>  # 对象统计
```

**解决方案**：
- 内存不足：增加 -Xmx
- 内存泄漏：分析堆转储
- GC 问题：调整 GC 参数

### 3. 数据库连接超时

**现象**：请求超时，数据库连接失败

**排查**：
```bash
show processlist;       # 连接数
show status like '%%'; # 状态
mysqladmin status      # 连接统计
```

**解决方案**：
- 连接池配置：增加连接数
- 慢查询：优化 SQL
- 数据库负载：读写分离

### 4. 磁盘空间不足

**现象**：写入失败，服务异常

**排查**：
```bash
df -h                  # 磁盘使用
du -sh /data/*         # 大文件
find / -mtime +30      # 旧文件
```

**解决方案**：
- 清理日志：删除/归档
- 清理数据：删除过期数据
- 扩容：增加存储

### 5. 高负载

**现象**：响应慢，CPU/IO 高

**排查**：
```bash
top -H                 # CPU 使用
iostat -x 1           # IO 使用
vmstat 1              # 系统状态
```

**解决方案**：
- 限流：配置限流策略
- 扩容：增加节点
- 优化：SQL/代码优化

### 6. 网络延迟高

**现象**：请求响应慢

**排查**：
```bash
ping <host>            # 延迟
traceroute <host>      # 路由
tcpdump -i eth0       # 抓包分析
```

**解决方案**：
- 网络优化：CDN/专线
- DNS 优化：Local DNS
- 协议优化：HTTP/2

## 故障级别定义

| 级别 | 定义 | 响应时间 | 解决时间 |
|------|------|----------|----------|
| P0 | 全线业务中断 | 15 分钟 | 2 小时 |
| P1 | 核心功能不可用 | 30 分钟 | 4 小时 |
| P2 | 次要功能异常 | 2 小时 | 8 小时 |
| P3 | 体验问题 | 4 小时 | 24 小时 |

---

## 故障升级机制

### 1. 升级条件

- 30 分钟未解决
- 需要更高权限
- 涉及多个部门

### 2. 升级路径

```
一线工程师 → 二线专家 → 研发负责人 → 总监
```
